# Atlas 评估套件 | DSIL SDK V0.1 开发者指南

## 文档定位

本文档面向两类读者：

1. **国内OEM客户**：希望在真实机器人系统中评估Atlas同步性能的工程团队
2. **DSIL SDK V0.1 领域专家**：需要理解锁定协议、模块职责和验收标准的国内OEM工程团队

在阅读本文档之前，建议先理解：
- 多传感器时间同步问题

- DSIL软件层架构

本文档的目标是：**让Atlas从架构概念走向可测量的系统行为验证**。

## 第一部分：评估套件概述

### 评估套件的目标

Atlas评估套件允许机器人团队使用真实的传感器组合来验证确定性多传感器同步。

该评估旨在回答一个核心问题：

> **Atlas能否减少跨传感器的时间戳漂移并简化传感器集成？**

一旦系统连接好，完整的评估通常在**30分钟内**即可完成。

### 申请评估套件

有兴趣评估Atlas的机器人团队可以申请评估套件。

申请时请提供：
- 公司/组织名称
- 联系人姓名和职位
- 机器人平台描述
- 当前传感器组合（摄像头、激光雷达、IMU等）
- 预计评估时间
- 收货地址

### 评估套件可用性

Atlas评估套件**免费**提供给符合条件的机器人开发团队，用于技术评估目的。

该评估计划的目标是：让工程团队在投入OEM集成试点之前，能够在自己的开发环境中验证Atlas的同步性能。

评估套件数量有限，分发给正在积极开发多传感器感知平台的机器人团队。

### 评估计划条款

| 项目 | 描述 |
| :--- | :--- |
| 费用 | 免费评估套件 |
| 评估周期 | 通常为2–3周 |
| 运输 | SensorDeck将套件寄送给评估团队 |
| 归还要求 | 评估期结束后必须归还套件 |
| 退货运费 | SensorDeck提供退货标签 |

评估套件始终为SensorDeck的财产，严格限于技术评估目的。

## 第二部分：评估套件硬件（V0.1锁定）

### 包含的硬件

Atlas评估套件包含一个**锁定的参考传感器组合**，旨在暴露跨多个时序域的真实同步问题。

| 组件 | 角色 | V0.1状态 |
| :--- | :--- | :--- |
| Fusion V2（GD32F407 + USB Hub） | 传感器聚合和时序骨干 | ✅ 锁定 |
| USB UVC摄像头（罗技C270） | 标准主机时间戳摄像头（Tier 3） | ✅ 锁定 |
| IMU（VectorNav VN-100） | 高速惯性传感器（Tier 1） | ✅ 锁定 |
| GNSS（u-blox ZED-F9P） | 全球PPS参考时钟（Tier 1） | ✅ 锁定 |
| GNSS天线 | PPS时序参考 | ✅ 包含 |
| 工业级USB线缆 | 传感器连接 | ✅ 包含 |
| PPS时序线缆 | GNSS → Atlas时序校准 | ✅ 包含 |

### 传感器时序等级定义

| 等级 | 定义 | V0.1传感器 |
| :--- | :--- | :--- |
| Tier 1 | PPS锚定，最高置信度 | ZED-F9P（PPS+UART）、VN-100（UART） |
| Tier 2 | 模型校正 | 例如： Gemini2 Ethernet LiDar （套件不包含）|
| Tier 3 | 到达时间基准 | C270（USB到达时间） |

### 硬件角色说明

**Fusion V2的职责：**
- 时间权威（Timing Authority）
- PPS驯服（PPS Discipline）
- 时间戳源（Timestamp Origin）
- CDC遥测（CDC Telemetry）
- 电源健康监控（Power Health）

**为什么选择这些传感器？**

该传感器组合特意包含了多个独立的时序域：
- ZED-F9P提供外部PPS参考
- VN-100提供高速惯性数据
- C270是标准的UVC摄像头（无硬件同步引脚）

这使评估能够清晰展示：**即使对于通常依赖主机时间戳的传感器，Atlas也能改善其时序对齐**。

### GNSS时序说明

随附的u-blox ZED-F9P GNSS接收器提供一个**PPS（脉冲每秒）时序参考**。

为获得最佳效果，GNSS天线应放置在：
- 靠近窗户
- 室外
- 或能部分看到天空的位置

**重要说明：** 如果无法获得GNSS锁定，Atlas也可以在**内部时间权威模式**下运行，从而允许在室内实验室或无直接天空视野的设施内进行评估。

## 第三部分：套件到达前的准备工作

大多数机器人团队可以在评估套件到达之前准备计算平台。

### 必需的计算平台

任何能够运行ROS2的Linux单板计算机或工作站。

**推荐配置：**
- NVIDIA Jetson Orin Nano / Xavier
- Intel NUC
- x86 ROS工作站

**推荐环境：**
| 组件 | 版本 |
| :--- | :--- |
| 操作系统 | Ubuntu 22.04 |
| ROS2 | Humble |
| Python | 3.10+ |

### 必需的网络与系统设置

系统应允许：
- USB设备访问（`/dev/ttyACM0`）
- ROS2主题传输
- 足够的USB带宽（多传感器流）

### 软件依赖项

安装以下ROS2驱动（这些驱动独立于Atlas运行）：

```bash
# USB摄像头驱动
sudo apt install ros-humble-usb-cam

# VectorNav IMU驱动
sudo apt install ros-humble-vectornav
```

这些驱动独立于 Atlas 运行。

**Atlas 不修改传感器固件或驱动程序。**

## 第五部分：30分钟评估流程

### 步骤1：连接传感器

按照下表连接各组件：

| 传感器 | 连接目标 |
| :--- | :--- |
| C270摄像头 | Fusion V2 USB端口 |
| VN-100 IMU | Fusion V2 UART |
| ZED-F9P GNSS | Fusion V2 UART + PPS |
| Fusion V2 | 主机USB（`/dev/ttyACM0`） |

---

### 步骤2：启动Atlas

执行以下命令启动Atlas：

```bash
dsil start
```

**预期输出：**

```bash
Fusion detected:      OK
PPS locked:           OK
Timing engine active: OK
Power health:         OK
PnP state:            READY
Sensors detected:     3/3
```
    
### 步骤3：启动传感器驱动

启动ROS2驱动（Atlas不替换这些驱动）：

    #### USB摄像头
    ros2 run usb_cam usb_cam_node_exe
    
    #### VN-100 IMU
    ros2 run vectornav vectornav_node
    
    #### 注意：ZED-F9P通过Fusion V2的CDC流输出，不需要单独启动驱动

验证话题：

```
ros2 topic list
```

**预期输出示例：**

```bash
/camera/image_raw
/imu/data
/atlas/status
/atlas/pps
/atlas/sync
/atlas/power_health
```

---

### 步骤4：基准时序测量（DSIL校正前）

测量跨传感器时间戳漂移：

    dsil_analyze --baseline --duration 30

示例结果：

```bash
    === 基准测量结果 (DSIL校正前) ===
    摄像头 ↔ 板卡时间 偏移: 15.2 ms (标准差: 3.1 ms)
    IMU    ↔ 板卡时间 偏移: 2.3 ms (标准差: 0.8 ms)
    GNSS   ↔ 板卡时间 偏移: 1.1 ms (标准差: 0.2 ms)
```
这确认了系统当前存在传感器时间未对齐的问题。

---

### 步骤5：激活DSIL同步

    dsil_sync --enable

DSIL应用动态时间戳偏移映射，将每个传感器的观测时间映射到Fusion V2硬件时序边界。

---

### 步骤6：验证同步效果（DSIL校正后）

```bash
dsil_sync_check
```

预期结果：

```bash
    === 同步后测量结果 (DSIL校正后) ===
    摄像头 ↔ 板卡时间 偏移: 0.7 ms (标准差: 0.2 ms)
    IMU    ↔ 板卡时间 偏移: 0.4 ms (标准差: 0.1 ms)
    GNSS   ↔ 板卡时间 偏移: 0.3 ms (标准差: 0.1 ms)
    
    === 通过标准 ===
    偏移 < 1 ms:     ✅ 通过
    稳定 > 30分钟:   ✅ 通过
    GNSS参考激活:    ✅ 通过
```
---

### 步骤7：查看电源健康状态

    dsil_power

预期输出：

```bash
    === 电源健康状态 ===
    VIN:       24.1 V
    5V_SYS:    5.02 V
    3V3:       3.30 V
    USB_PORT1: OK
    USB_PORT2: OK
    USB_PORT3: OK
    STATE:     OK
    Stale:     0 ms
```
---

### 步骤8：生成可视化图表

    dsil_plot --output ./sync_results

输出文件：

- `offset_before.png`：校正前的偏移分布
- `offset_after.png`：校正后的偏移分布
- `timeline.png`：30分钟稳定性时间线

## CTO 推荐摘要
典型的内部推荐结构：

**问题**
多传感器感知堆栈存在时间戳漂移和集成复杂的问题。

**Atlas 结果**
在摄像头和IMU之间建立了确定性的时序边界。

**影响**
*   改善了 SLAM 的传感器对齐
*   减少了感知管道的不确定性
*   简化了集成架构

**建议：**
推进至 OEM 集成试点评估。

## 评估后的步骤
如果评估显示出价值，团队通常会进入**白标 OEM 集成试点**阶段。

该试点阶段旨在将 Atlas 适配到量产机器人平台。

### OEM 试点计划包括
*   定制连接器配置
*   传感器接口映射
*   电源分配设计
*   机械安装集成
*   软件集成支持

该试点计划将产出一个为机器人平台定制的白标 Atlas 参考设计。

## OEM 部署验证
在 OEM 试点阶段，将在真实的机器人系统内进行第二次验证。

**验证的指标：**
*   完整机器人传感器同步
*   感知管道稳定性
*   系统延迟影响
*   部署可靠性
*   功耗与热行为

验证通过后，Atlas 将成为机器人量产传感器基础设施的一部分。

## 第八部分：总结

### 评估验证的核心能力

至此，Atlas评估套件已验证了以下能力：

1. 确定性时序边界：通过 PPS 驯服和 board_time_us 单一时间源
2. 跨传感器同步：偏移小于 1 ms，稳定运行超过 30 分钟
3. 电源健康可观测：CLI 和 ROS2 双路可见
4. 即插即用：上电后自动检测、初始化、启动
5. 零驱动修改：完全兼容现有 ROS2 驱动

### 核心价值回顾

> Atlas = ROS2之下的时间基础设施层 + 完整可观测性

- 不再猜测时序问题
- 不再盲调传感器融合
- 不再为时间漂移困惑
- 不再抱着万用表守现场

### OEM 集成路径
Atlas 旨在直接从评估过渡到 OEM 部署。

您可以通过三种方式将 Atlas 集成到您的产品中：

-   使用 Atlas 作为参考集成平台
-   将 Atlas 嵌入您的系统架构
-   通过白标 (OEM) 集成计划采用 Atlas

Atlas 消除了重新设计以下系统的需求：

-   传感器布线架构
-   时序同步系统
-   板载电源分配

### 团队转向量产的原因
评估后，机器人团队通常会继续推进，因为：

-   集成模型无需更改驱动程序
-   确定性时序提高了系统可靠性
-   系统架构变得更简单、更具可扩展性

Atlas 用可重用的基础设施层取代了重复性的工程工作。
